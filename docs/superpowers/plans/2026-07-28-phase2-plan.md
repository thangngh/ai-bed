# Phase 2 Implementation Plan — Complete Data Flow, History UX & Infrastructure

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete data flow from FE FormScreen to Engine prompt, add story history UX, and add Docker infrastructure.

**Architecture:** Extend existing DTO chain (FE → BE → Engine) with gender/favoriteCharacter fields, standardize section contract, connect Feedback + Saved Stories to BE API, add Docker compose for production-like dev.

**Tech Stack:** NestJS 11 (TypeORM, class-validator), Python FastAPI (openai, google-genai), React 19 (Vite), Bottleneck queue, dual SQLite.

## Global Constraints

- All prompt instructions in English, story output in Vietnamese (thuần Việt)
- Tenant = device UUID, attached as `X-Tenant-Id` header
- Dual SQLite: core.db (tenant, child, feedback) + local.db (story, section, memory)
- Gender field only allows `'boy' | 'girl' | 'unspecified'`
- favorite_character is free text, sanitized by engine output validator safety blocklist
- All API responses use `{ data: ... }` or `{ error: { code, message }, request_id }` envelope
- DELETE /story/:id is tenant-scoped (hard delete)
- `isSaved` flag defaults to 1 (true) on story creation
- Engine /generate endpoint validates required fields `child_name`, `age`, `theme`
- Docker compose uses health check chaining: engine → backend → frontend

# Engine/core/validator.py
REQUIRED_SECTION_TYPES = {"opening", "context", "conflict", "resolution"}
OPTIONAL_SECTION_TYPES = {"interaction_1", "interaction_2", "interaction_3", "moral"}

class ValidationResult:
    def __init__(self, valid: bool, errors: list = None, fixed_data: dict = None):
        self.valid = valid
        self.errors = errors or []
        self.fixed_data = fixed_data

class OutputValidator:
    # ... existing methods ...

    def validate_sections(self, sections: list[dict]) -> ValidationResult:
        errors = []
        present_types = {s.get("type") for s in sections}
        missing = REQUIRED_SECTION_TYPES - present_types
        if missing:
            errors.append(f"Missing required sections: {', '.join(sorted(missing))}")
        for idx, s in enumerate(sections):
            if not s.get("type"):
                errors.append(f"Section {idx}: missing 'type'")
            if not s.get("text") and s.get("type") not in OPTIONAL_SECTION_TYPES:
                errors.append(f"Section {idx} ({s.get('type')}): missing 'text'")
        return ValidationResult(valid=len(errors) == 0, errors=errors)
```

// FE/src/utils/storyGenerator.ts — replace inline mapping with SECTION_MAP
const SECTION_MAP: Record<string, keyof StorySegments> = {
  opening: 'opening',
  context: 'situation',
  conflict: 'challenge',
  resolution: 'ending',
  interaction_1: 'interaction1',
  interaction_2: 'interaction2',
  interaction_3: 'interaction3',
  moral: 'moralSummary',
};

function mapSectionsToSegments(sections: any[]): StorySegments {
  const segments: Partial<StorySegments> = {};
  for (const section of sections) {
    const segmentKey = SECTION_MAP[section.type];
    if (segmentKey) {
      segments[segmentKey] = section.text || section.prompt || '';
    }
  }
  // Fill empty segments with fallback values
  return {
    opening: segments.opening || '',
    situation: segments.situation || '',
    interaction1: segments.interaction1 || '',
    challenge: segments.challenge || '',
    interaction2: segments.interaction2 || sections.find(s => s.type === 'interaction')?.prompt || '',
    ending: segments.ending || '',
    interaction3: segments.interaction3 || '',
    moralSummary: segments.moralSummary || sections.find(s => s.type === 'moral_summary')?.text || '',
  };
}
```
